# Сетевой Модуль Flux (src/content/network)

## Введение

Модуль `src/content/network` является основой сетевой подсистемы фреймворка Flux. Он разработан с учетом принципов и архитектуры, вдохновленных сетевым стеком Google Chromium, предоставляя мощные, гибкие и безопасные инструменты для обработки всех сетевых запросов и взаимодействий. Этот модуль отвечает за работу с протоколами HTTP, HTTPS, WebSockets, QUIC, FTP, а также за управление DNS, прокси, SSL/TLS сертификатами и низкоуровневыми сокетами.

## Основные возможности

*   **Полный сетевой стек:** Реализация поддержки основных интернет-протоколов, включая HTTP/1.1, HTTP/2, HTTP/3 (QUIC), WebSocket, FTP.
*   **Обработка URL:** Полная поддержка парсинга, валидации и нормализации URL.
*   **Управление запросами/ответами:** Создание, отправка и обработка сетевых запросов и ответов, включая заголовки, тело и статус.
*   **Кэширование:** Интегрированный HTTP-кэш для ускорения загрузки ресурсов.
*   **Безопасность:**
    *   Поддержка SSL/TLS для HTTPS и других защищенных соединений.
    *   Проверка SSL-сертификатов.
    *   Интеграция с системами управления сертификатами.
*   **DNS-разрешение:** Эффективное разрешение доменных имен с поддержкой кэширования DNS-записей.
*   **Прокси-серверы:** Поддержка различных типов прокси-серверов (HTTP, SOCKS) и автоматическое определение прокси.
*   **Низкоуровневые сокеты:** Работа с TCP, UDP, SSL/TLS сокетами.
*   **Сетевая логика:** Система логирования всех сетевых событий для отладки.
*   **Асинхронная модель:** Построена на асинхронной архитектуре для высокой производительности и отзывчивости.

## Архитектура

Сетевой модуль Flux имеет многоуровневую архитектуру, вдохновленную Chromium:

*   **Core (`core/`):** Управляет сетевым контекстом, сервисными компонентами и задачами.
    *   `NetworkContext`: Контекст для изоляции сетевых ресурсов.
    *   `NetworkService`: Основной сервис, предоставляющий сетевые API.
*   **URL (`url/`):** Работа с URL, парсинг, запросы.
    *   `URLRequest`: Основной класс для выполнения запросов.
    *   `URLRequestContext`: Конфигурация для одного запроса.
*   **Протоколы (`http/`, `ftp/`, `websocket/`, `quic/`, `spdy/`):** Реализации конкретных протоколов.
    *   `HttpNetworkSession`: Управляет соединениями для HTTP/2.
    *   `QuicStream`: Потоки для протокола QUIC.
*   **Сокеты (`socket/`):** Низкоуровневая работа с соединениями.
    *   `TcpClientSocket`, `SslClientSocket`: Реализации клиентских сокетов.
*   **Прокси (`proxy/`):** Логика работы с прокси-серверами.
*   **Сертификаты (`cert/`):** Управление SSL/TLS сертификатами.
    *   `CertVerifier`: Проверка подлинности сертификатов.
*   **DNS (`dns/`):** Разрешение доменных имен.
    *   `HostResolver`: Определение IP-адресов по именам хостов.
*   **Transport (`transport/`):** Низкоуровневые транспортные протоколы.
*   **Util (`network_util/`):** Вспомогательные утилиты.

## Протоколы

### HTTP(S)

*   **HTTP/1.1:** Полная поддержка.
*   **HTTP/2:** Реализован для оптимизации многопоточности и уменьшения задержек.
*   **HTTP/3 (QUIC):** Поддержка протокола QUIC для более быстрого и надежного соединения поверх UDP.
*   **HTTPS:** Использует SSL/TLS для защищенных соединений.

### WebSocket

Реализована поддержка протокола WebSocket для двусторонней связи в реальном времени.

### FTP

Базовая поддержка протокола FTP для передачи файлов.

## Безопасность

*   **SSL/TLS:** Поддержка современных версий TLS для шифрования трафика.
*   **Проверка сертификатов:** Механизмы проверки подлинности SSL-сертификатов для предотвращения атак "человек посередине".
*   **Управление сертификатами:** Интеграция с системными или собственными хранилищами сертификатов.

## DNS-разрешение

*   **Кэширование DNS:** Для ускорения повторных запросов.
*   **Параллельное разрешение:** Возможность одновременного запроса нескольких DNS-серверов.
*   **Поддержка IPv6:** Полноценная работа с IP-адресами IPv6.

## Прокси

*   **Поддержка форматов:** PAC-файлы, прямые настройки прокси.
*   **Типы прокси:** HTTP, HTTPS, SOCKS4, SOCKS5.

## Асинхронная модель

Весь сетевой стек построен на асинхронной модели событий (event-driven). Это позволяет обрабатывать множество сетевых операций одновременно, не блокируя основной поток выполнения приложения. Используются концепции, аналогичные `MessageLoop` и `NetLog` из Chromium.

#include "src/content/network/network_service.h"
#include "src/content/network/http/http_network_session.h"
#include "src/content/network/socket/tcp_client_socket.h"
#include "src/content/network/dns/host_resolver.h"

// ... предположим, у нас есть NetworkService и подходящий контекст ...

// Инициализация сетевого контекста
network::NetworkContext network_context(network_service.get(),
                                       network_context_getter,
                                       network_service_delegate);
